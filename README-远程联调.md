# 客户实机与远程联调

本材料配合当前包的二进制 SHA 和真实测试报告使用。内部离线、pluginval、localhost 自检分别记录；它们不等于客户 DAW、真实声卡、互联网链路或全部功能验收通过。

## 先确认身份与复现条件

在发行包根目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\Collect-Diagnostics.ps1`。它只生成本地 JSON 与复现模板，不上传内容、不访问节点、不打开声卡，不读取邀请码、配置文件、用户工程或音频。由客户自行检查后分享。

记录：产品及宿主版本、Windows/驱动、双方采样率和块长、输入/输出路由、实际步骤和时间。保留原版本与工程，先在测试通道使用；不要用正在工作的母线进行首次排查。

## Connect：分层核对

1. 先在同机启动包内节点并运行 Verify-Local。报告是合成回调的本机证据，不代表声卡延迟。失败日志保留，不修改阈值后挑一次通过。
2. 确认发送通道确有宿主输入，接收通道接本地监听，禁止把接收输出回送给同一发送通道；双方用耳机控制反馈风险。
3. 公网先核对真实 HTTPS 节点 health/API 与 UDP 双向。控制接口响应成功不等于音频已打通。若有 `tools/Test-Node.ps1`，先读其帮助，按对应版本的参数生成本地结果；不要把健康检查当成端到端音频验收。
4. 最后在两台独立机器进行实际输入/输出与中断、重连、退出复验。当前尚无新的完整公网 native 音频通过证据，不承诺跨省 10ms、硬件往返或固定容量。Network RTT 不能代替 Audio RTT。

## Headphone：分层核对

先按准确型号选档案，分别核对 0/100/200%、旁通与干湿对齐、HOST/MANUAL 来源、宿主自动化及状态恢复。Correction 图表不是耳边实测曲线；legacy 监听模式只为旧工程兼容，在高级入口中单独说明。客户实际听音结果与离线 FIR/oracle 误差分开记录。

## 共享资料

只分享已检查的 diagnostics.json、复现模板与必要截图/日志。遮住 HM1 邀请码、密钥、令牌、账号和私人目录；不要上传音频或用户工程。应用不会自动发消息或上传。数据集/目标曲线商业再分发授权、真实 DAW 长期兼容和真实 Windows DPI 均须独立验收。

本机GUIDE由产品内嵌离线HTML提供，点击后才导出到AppData/HONESTMIX/Documentation；官网private不应被误诊为插件安装失败。DOMAIN/TLS/API/UDP未通过时先修节点，不要求客户重复重装或交换发起者绕过HTTPS。

控制面特别说明：发起者Create和加入者Join都会发送并验证HTTPS请求。加入者不必手工填节点，只是因为连接码已携带地址，并不跳过TLS。节点域名/证书/服务故障不应靠交换发起者规避。
